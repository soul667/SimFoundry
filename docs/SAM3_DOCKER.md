# Standalone SAM3 Docker

This image contains the SAM3 runtime and pinned SAM3 source code only. It does **not** contain model weights and it does **not** download model weights at runtime.

Image name after merge/publish:

```text
ghcr.io/soul667/simfoundry-sam3:latest
```

The SAM3 source revision is pinned to the same revision used by SimFoundry's installer:

```text
46957e47805eaa273f4aa7bbbd25a88bca9108ce
```

## Weight lifecycle

Keep weights outside Docker:

```text
Hugging Face private model repo
        |
        | hf download (host only, once/update)
        v
/srv/simfoundry-models/sam3.pt
        |
        | Docker bind mount :ro
        v
/models/sam3.pt inside container
```

The container sets `HF_HUB_OFFLINE=1` and calls `build_sam3_image_model(..., load_from_HF=False)`. Missing `/models/sam3.pt` is therefore an immediate error rather than a network download.

## Stage the checkpoint in your own Hugging Face repo

First obtain the official-compatible checkpoint under the applicable Meta SAM license. Redistribution of SAM Materials is subject to that license, so keep a copy of the SAM license next to the checkpoint. A private repository is the default recommendation for this workflow.

Install the current Hub client and authenticate on the host/workstation:

```bash
python -m pip install -U huggingface_hub
hf auth login
```

If your SimFoundry checkout has installed SAM3 under `deps/sam3`, stage the checkpoint and license with:

```bash
python scripts/model_weights/upload_sam3_to_hf.py \
  --repo-id YOUR_HF_USER/simfoundry-sam3-weights \
  --checkpoint /path/to/sam3.pt \
  --license deps/sam3/LICENSE
```

The helper creates the model repo as **private** unless `--public` is explicitly supplied, then uploads:

```text
sam3.pt
LICENSE
```

## Materialize the weights on a server

This is performed outside Docker:

```bash
python -m pip install -U huggingface_hub
hf auth login

bash scripts/model_weights/download_sam3_from_hf.sh \
  YOUR_HF_USER/simfoundry-sam3-weights \
  /srv/simfoundry-models
```

The resulting file is:

```text
/srv/simfoundry-models/sam3.pt
```

You can pin a Hugging Face branch/tag/commit as the optional third argument to the helper.

## Run SAM3

```bash
docker run --rm --gpus all \
  -v /srv/simfoundry-models:/models:ro \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/sam3_out:/output" \
  ghcr.io/soul667/simfoundry-sam3:latest \
  --image /input/frame.png \
  --prompt "cup" \
  --output-dir /output
```

The default checkpoint path is `/models/sam3.pt`. A different mounted path can be supplied explicitly:

```bash
--checkpoint /models/other-sam3.pt
```

For one prompt, produce a mask at a path directly consumable by the RGB-D registration service:

```bash
docker run --rm --gpus all \
  -v /srv/simfoundry-models:/models:ro \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/sam3_out:/output" \
  ghcr.io/soul667/simfoundry-sam3:latest \
  --image /input/frame.png \
  --prompt "cup" \
  --mask-out /output/object_mask.png \
  --output-dir /output
```

Outputs include the selected mask, all matched instance masks, scores/boxes metadata, and RGBA cutouts suitable for sending to an external object reconstruction service such as Meshy.

## Meshy GLB -> RGB-D registration

The existing `rgbd-registration` image already supports external meshes in explicit-file mode. A Meshy-exported GLB can therefore replace SimFoundry Stage 7 entirely:

```bash
docker run --rm \
  -v "$PWD/input:/input:ro" \
  -v "$PWD/sam3_out:/sam3:ro" \
  -v "$PWD/meshy:/meshy:ro" \
  -v "$PWD/reg_out:/output" \
  ghcr.io/soul667/simfoundry-rgbd-registration:latest \
  --rgb /input/frame.png \
  --depth /input/depth.npy \
  --intrinsics /input/K.npy \
  --mask /sam3/object_mask.png \
  --mesh /meshy/object.glb \
  --camera-to-world /input/T_cam_world.npy \
  --output-dir /output
```

The registration service samples the GLB mesh with Trimesh, estimates the initial scale from the RGB-D partial-object point cloud using the OBB diagonal ratio, and then performs the existing CPD similarity/pose fitting. It does not depend on the mesh having been generated by Hunyuan3D or TRELLIS.

If `--camera-to-world` is unavailable, registration can still recover the mesh pose in the camera frame; world-frame output is simply omitted.
